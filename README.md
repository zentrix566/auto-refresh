# 页面保活助手

Chrome 浏览器扩展（Manifest V3），按固定间隔自动刷新指定域名下的所有标签页，让会话保持登录，避免长时间无操作被系统踢出。默认域名为空，安装后在弹窗里添加自己的站点即可。

## 主要功能

- 到点把生效域名下的所有标签页刷新一遍，支持**静默保活**：向页面注入隐藏 iframe 续会话，页面不闪烁、不丢表单
- 生效域名按条管理，**每个域名可设置独立刷新间隔**；支持逗号、分号或空白分隔批量添加，子域名自动包含，直接粘贴完整 URL 也能自动提取域名
- 刷新间隔 1~1440 分钟可调，默认 5 分钟；域名列表默认为空，点「当前页域名」一键填入或手动输入
- **随机抖动**：间隔在设定值上 ±20% 浮动，请求模式更像人工操作；关闭则准点刷新
- **仅时段内保活**：可限定保活时段（支持跨午夜，如 22:00–06:00），时段外到点只跳过不刷新
- 页面停在登录地址时发桌面通知提醒会话可能失效（按域名节流，30 分钟内不重复弹），日志同步记录
- 一键为没有打开页面的域名补一个固定的后台保活标签页
- 启用后扩展图标显示绿色 **ON** 角标，一眼确认保活正在运行
- 浏览器关闭再打开后任务自动恢复；定时器意外丢失时会自动重建
- 弹窗实时显示下次刷新倒计时、上次刷新时间、累计执行次数和运行日志（日志持久化，重启后仍可查看）
- 正在加载中的页面本次跳过，避免打断；被 Chrome 内存优化「丢弃」的后台标签页同样会被刷新拉起

## 运行方式

本项目是纯静态的浏览器扩展，**没有任何第三方依赖，不需要 `npm install`**。开发用脚本只依赖 Node.js 内置模块（建议 Node 18 及以上）。

### 开发模式加载

1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 打开右上角的 **开发者模式** 开关
3. 点击 **加载已解压的扩展程序**，选择本项目的根目录（包含 `manifest.json` 的那一层）
4. 修改代码后，回到扩展页点击卡片上的刷新按钮重新加载（改动 `background.js` 后必须刷新）

### 构建分发包

```bash
node tools/build.js
```

产物输出到 `dist/auto-refresh-v<版本号>.zip`，只包含运行必需的文件（`manifest.json`、`background.js`、`popup/`、`icons/`），不含 README、构建脚本等开发文件。

### 权限说明

- `alarms` 定时触发刷新；`tabs` 读取标签页地址并刷新；`storage` 保存配置和日志
- `scripting` + http/https 主机权限：开启静默保活时向页面注入隐藏 iframe 使用
- `notifications`：会话可能失效时的桌面提醒使用

## 使用步骤

1. 在浏览器里打开并登录要保活的页面
2. 点击工具栏上的扩展图标打开弹窗
3. 点「当前页域名」把当前页面的域名加进生效域名列表，或直接输入域名回车；每个域名可单独调整刷新间隔
4. 按需勾选静默刷新、随机抖动、仅时段内保活
5. 点「启用保活」，图标出现 **ON** 角标即表示已生效
6. 想立刻验证效果就点「立即刷新」，到日志里看执行结果

弹窗关闭后，Service Worker 会按周期自动执行，不需要保持弹窗打开。匹配域名的标签页一个都没打开时，只记一条日志跳过本次，不会报错。

## 实现说明

定时器使用 `chrome.alarms` 而不是 `setTimeout`，因为 Manifest V3 的 Service Worker 会在空闲时被休眠，`chrome.alarms` 能跨休眠持续触发，也支持浏览器重启后继续运行。

配置、执行计数和日志全部存在 `chrome.storage.local`，Service Worker 被杀掉重启后不依赖内存状态：每个入口（定时器触发、弹窗消息、浏览器启动）都先从 storage 重新读取配置再执行。这样避免了「worker 刚被唤醒时拿着未恢复的默认配置执行、刷新被静默跳过」的问题。每轮执行完会清掉并重建 alarm，既应用最新的间隔设置，也能自愈被系统清掉的定时器。
